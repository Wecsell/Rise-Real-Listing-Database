# Как вернуть автоматический разбор (Gemini)

Разбор выключен намеренно **06.08.2026** по решению владельца: таблица заполняется вручную, пока не
зафиксированы правила заполнения. Ключ не удалён и код не вырезан — включение делается одной строкой.

Этот файл существует, чтобы через месяц не пришлось выяснять по коду, что было отключено и почему.

## Включение

```bash
# .env
LLM_BACKEND=gemini
GEMINI_API_KEY=<ключ>
```

Правок в коде не требуется. Проверка:

```bash
python -c "from dotenv import load_dotenv; load_dotenv(override=True); from app import llm_gate; print(llm_gate.backend(), llm_gate.llm_enabled())"
```

Ожидаемо: `gemini True`. Если `off` — не подхватился `.env`; если `gemini False` — нет ключа.

## Что именно выключено

Единственный выключатель — [`app/llm_gate.py`](app/llm_gate.py). Через него проходят все обращения:

| Модуль | Что делает через LLM |
|---|---|
| `app/gemini_parser.py` | разбор сообщений чата (`parse_message`) |
| `app/link_fetcher.py` | разбор шахматок и страниц по ссылкам |
| `app/field_extractor.py` | поиск отдельного поля в документе (клиент импортирует из `gemini_parser`) |
| `app/doc_parser.py` | разбор PDF (клиент импортирует из `gemini_parser`) |

Клиент **не создаётся**, пока `llm_gate.llm_enabled()` не вернёт True. Наличия одного ключа в окружении
недостаточно — так сделано, чтобы случайно попавший в окружение ключ не включал API молча.

## Чего ждать при включении

- **Поведение при выключенном разборе:** извлечение возвращает `status = "manual_required"`, а
  `is_relevant` остаётся `None` — вердикта о источнике не выносится. Прежний код ставил
  `is_relevant: False`, то есть сообщение застройщика молча признавалось нерелевантным. Если увидите
  этот статус после включения — значит API всё ещё не активен.
- **Кэш не сбрасывается.** `content_cache` хранит результаты разбора по хэшу содержимого. Всё, что
  заполнено вручную, в кэш не попадает, поэтому первый прогон с API пройдёт по источникам заново и
  может предложить свои значения. Ручные значения приоритетнее: сверяйте `Gaps` до и после.
- **Контракт полей один и тот же** — `gemini_parser.EXTRACTION_PROMPT`. Он же служил инструкцией при
  ручном заполнении, поэтому смысл сохранённых значений при переключении не меняется.

## Ручной режим

Пока API выключен, записи вносятся через [`tools_manual_intake.py`](tools_manual_intake.py) — он идёт
через те же `upsert_developer` / `upsert_project` / `upsert_unit`, что и автоматический разбор, поэтому
каноны базы (списки select, порядок координат «долгота, широта», формат `Key`, пересчёт `Gaps`)
соблюдаются одинаково:

```bash
python tools_manual_intake.py data/manual/pce.json          # проверка, ничего не пишется
python tools_manual_intake.py data/manual/pce.json --apply   # запись
```

Прямые PATCH-запросы в Airtable в обход этого инструмента запрещены: они обходят валидацию и расходятся
с тем, что позже запишет модель.

Полный регламент разбора — [`.agent/rules/rules.md`](.agent/rules/rules.md), раздел «Intake pipeline».
